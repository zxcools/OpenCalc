## 一、确认的缺陷

### 1. 【P1 · 数据安全】备份导入 / 切换数据目录时，单条写库失败被静默吞掉

**位置**
- `main.py:2358-2362`（交易记录）、`2365-2369`（监控池）、`2372-2377`（复盘）
- `main.py:1655-1668`（切换数据目录的迁移，同样写法）

```python
try:
    trade_import_record(r)   # 写 trade_records
    imported += 1
except Exception:
    pass   # 单条记录不合法则跳过, 不中断整批
```

**现象**：任何一条记录写库抛异常（少字段、类型不对、主键冲突、库被锁），都会被 `pass` 吞掉；前端只拿到 `imported` 计数，
提示仍为「✅ 导入成功：共 N 条」（`main.py:8879` 附近）。用户**不知道少了几条**。

**影响**：这是真正的「看着成功其实丢了数据」。导入/迁移是一次性动作，事后很难发现少的是哪几条。
（`trade_import_record` 用的是 `INSERT OR REPLACE` 保留原 id，本身设计是对的，问题只在这个吞异常的循环。）

**建议**：改成累计失败条数与原因，返回值带上 `failed` / `failed_ids`，前端在提示里明确写出
「成功 N 条，失败 M 条（第 X 条：原因）」，至少给出前 3 条明细。同一处 `1655-1668` 一并处理。

### 2. 【P1 · 我上轮引入】「按平仓时间」+ 非「全部」区间时，统计卡的「持仓中」恒为 0

**位置**：`main.py:7482`（`holding: gs.length - flat`），渲染在 `main.py:7581`

**成因**：v50.76 我把统计口径换成了 `scopedGroups()`（`main.py:7397`）。当区间口径选「按平仓时间」时，
**未平仓记录因为没有平仓日期会被整条过滤掉** → `flat === gs.length` → `holding` 恒等于 0。

**影响**：用户实际有 6 笔持仓（真实库 16 条里 6 条未平），卡片却写「持仓中: 0 · 共 10 条」，
与「未平仓记录没有平仓时间，不计入」的说明文字自相矛盾。这是每天都会看到的错误数字。

**建议**（两种口径，需用户定）：
- (a) 「持仓中」不受区间影响，始终按全量算 —— 区间是「已实现战绩」的口径，不该改变持仓数；
- (b) 保持现状，但在「按平仓时间」时把「持仓中」这一格隐藏或显示为「—」并加 tooltip 说明。

### 3. 【P2 · 安全】内置文件夹浏览器的目录名未转义（XSS）

**位置**
- `main.py:9163-9165`：盘符 `dr` 直接拼进 `data-pickdrive="..."` 与标签体
- `main.py:9170-9172`：**目录名 `n`** 直接拼进 `data-pickdir="..."` 与标签体
- `main.py:9176` / `9182`：`d.error` 与异常对象 `e` 直接拼进 `innerHTML`

```js
return '<div data-pickdir="' + n + '" style="...">📁 <span style="flex:1">' + n + '</span></div>';
```

数据源是 `main.py:1825` 的 `dirs.append(e.name)` —— **文件系统原始目录名**。
在任意被浏览的目录下建一个名为 `"><img src=x onerror=...>` 的文件夹，点「⚙ 数据位置 → 浏览」时即可逃逸属性执行脚本。

**影响**：本机是自己的机器，实际风险有限（不是远程攻击面），但属明确的注入缺口，
且同文件其它所有渲染位置都规规矩矩走了 `escHtml()`，这里是漏网。

**建议**：这三处（含 `9117` 的备份文件名 `b.name`）统一套 `escHtml()`。`escHtml` 已覆盖 `& < > " '`，直接可用。

### 4. 【P2 · 手续费】`trade_day` 夜盘「+1 天」不跳周末与节假日 → 平今被误判成平昨

**位置**：`main.py:342-346`

```python
if int(m.group(1)) >= 21:          # 21:00 之后 → 下一交易日
    return (datetime.strptime(d, "%Y-%m-%d") + timedelta(days=1)).strftime("%Y-%m-%d")
```

**现象**：只做 `+1 天`，不认识交易日历。**周五 21:30** 开的仓，交易日应为**下周一**，函数返回**周六**；
于是与「周一 09:30 平仓」比较时字符串不相等 → `row_fee`（`main.py:395-397`）判成**平昨**，而正确应为**平今**。
长假前的夜盘同理（节前一晚 → 应跳到节后第一个交易日）。

**影响**：不少品种平今免费或更便宜，这里会**多算手续费**；净盈亏与「净盈亏比」随之偏低。
v50.74 加的「平今/平昨」手选可以兜住，但那是手工补救，自动判定本身是错的。

**建议**：加一张最小的交易日历（或「跳周六周日 + 一张节假日表」）。节假日表需要维护，
可以只做「跳周末」+ 手动覆盖常用长假，并在说明里写清边界。**要先确认用户是否在意这块。**

### 5. 【P3 · 资源】备份列表的只读连接在异常路径下泄漏

**位置**：`main.py:1290-1296`

```python
try:
    c = sqlite3.connect("file:%s?mode=ro" % p..., uri=True)
    item["records"] = c.execute("SELECT COUNT(*) FROM records").fetchone()[0]
    item["trades"] = c.execute("SELECT COUNT(*) FROM trade_records").fetchone()[0]
    c.close()          # ← 第二条 execute 抛错就跳过了

    pass
```

缺 `finally`。同文件 `main.py:1084` 的 `_write_backup_meta` 已有正确写法（`try/finally` 关连接）可直接对照。
触发条件很现实：**老备份缺 `trade_records` 表**时第二条 `execute` 就会抛。

**建议**：照 `1084` 的写法加 `finally`。

### 6. 【P3 · 并发】备份相关全局量在 `ThreadingHTTPServer` 下无锁

**位置**
- `main.py:1042-1044` `_last_backup_ts` / `_pending_backup_meta`，读-判断-写于 `1215-1219`、`1236-1244`
- `main.py:1014` `FUND_DB_CONN`：每请求线程都会改写（`1874`），而 `restore`（`1341-1346`）与
  切换目录（`1633-1638`）会把它 **close 并置 None** → 可能关掉另一个线程正在用的连接
- `main.py:1846` `_DB_SCHEMA_FOR`：`_fund_db` 内受锁保护，但 `1347` / `1639` 在**锁外**直接置 None

**影响**：并发保存时可能重复生成备份（多占一个轮转位）、丢掉被合并的 reason；
概率低，但「恢复备份 / 切换数据目录」是重要操作，撞上会报奇怪的错。

**建议**：复用已有的 `_DB_LOCK`（`main.py:1845`）把这几处包起来；`_last_backup_ts` 那块单独加一把小锁。

## 二、可选的优化与新功能

按「与现有用法贴合度」排序：

1. **统计区间补「自定义起止日」**（+ 季度 / 半年档位）——现在的 5 档是固定窗口，跨年比业绩时经常要自定区间。
   位置现成：`#rangeBar`（`main.py:5290`）加一段、`rangeFrom()`（`main.py:7381`）加分支即可。
2. **按平仓时间时的口径修正**（即上面缺陷 2）。
3. **导出当前筛选结果为 CSV**——主表已经能按区间 + 搜索筛出「这一段、这些品种」，把这些行导出，写复盘/知乎时直接取数。
   复用现有导出按钮的位置，前端拼 CSV 即可，不需要改库。
4. **品种维度盈亏排行**——用户是「按品种分开跟踪」的习惯，加一个「哪个品种贡献最多 / 亏最多」的表或小条形图，
   比只看总数有用。
5. **平仓弹窗直接显示两档手续费金额**（如「平今 ¥0.02 / 平昨 ¥8.62」）——v50.74 加了手选档位，但选的时候看不到钱差多少，
   要把费率表开个小接口给前端。**这是我上一轮提过、还没定的那件事。**
6. **未平仓头寸风险汇总**——当前所有未平仓的：占用保证金 / 权利金合计、理论最大亏损、距止损的距离。
   风控口径与用户「单笔权利金 ≤3%」的铁律直接对应。
7. **主表点列头排序**（按盈亏 / 开仓日 / 品种）——现在固定「按开仓时间倒序」。
8. **恢复备份前预览差异**——v50.75 已经能显示「最后变更内容」，再进一步：这份备份比当前少/多了哪些记录、
   时间跨度到哪天，恢复前能判断得更准。
